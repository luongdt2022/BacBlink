# Implementation Plan: Intake AI Processing Notification

**Branch**: `003-intake-ai-processing-notification` | **Date**: 2026-03-26 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/003-intake-ai-processing-notification/spec.md`

## Summary

After creating or updating an intake on the user site, show a 5-second Sonner toast: "Đang chờ AI xử lý nội dung. App sẽ thông báo cho bạn khi hoàn thiện." In the intake list, display AI processing status badges in the "Trạng thái" column and disable row clicks for items where AI is still processing (`aiProcessingStatus === 'processing'`) or has not run (`aiProcessingStatus === null`).

## Phase 0 — Research

Research documented in `research.md`. Key findings:

1. **AI status field**: `aiProcessingStatus` on `Intake` entity. Set to `PROCESSING` on create/update (when content exists), updated asynchronously to `COMPLETED`/`FAILED`.
2. **Toast library**: Sonner already installed and used throughout codebase.
3. **Row disabling**: Two-layer approach — visual dimming (`opacity-50 cursor-not-allowed`) + functional guard in `handleRowClick`.
4. **Null status**: Intakes without content have `aiProcessingStatus === null`. These should also be disabled since AI never ran.
5. **Action buttons preserved**: Edit/delete use `stopPropagation` — unaffected by row disabling.

### How AI processing is triggered (reference only)

```typescript
// dmst-backend/src/intakes/intakes.service.ts — create() method
if (savedIntake.content) {
  await this.intakeRepository.update(savedIntake.id, {
    aiProcessingStatus: AiProcessingStatus.PROCESSING,
  });
  void this.applyAiProcessing(savedIntake);  // fire-and-forget
}
```
